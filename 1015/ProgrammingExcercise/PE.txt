Suggestions for Testing Your Code — 코드 테스트 방법
1. 디버거로 단계별 실행하기
프로그램을 처음 테스트할 때는 항상 디버거를 사용하여 한 단계씩 실행한다. 작은 세부 사항을 놓치기 쉽기 때문에, 디버거를 통해 프로그램이 실제로 어떻게 동작하는지 정확하게 확인한다.

2. 부호 있는 배열에 음수 포함하기
프로그램 명세에서 부호 있는 배열(signed array)을 요구한다면, 테스트 데이터에 반드시 음수 값을 포함한다.

3. 경계값 테스트하기
입력값의 범위가 지정되어 있다면 다음 세 가지 경우를 포함하여 테스트한다.

경계값보다 작은 값

경계값과 같은 값

경계값보다 큰 값

4. 다양한 길이의 배열로 테스트하기
배열의 길이가 서로 다른 여러 테스트 케이스를 작성하여 프로그램을 테스트한다.

5. Memory 창으로 배열 확인하기
배열에 값을 기록하는 프로그램을 작성했다면, Visual Studio 디버거의 Memory 창을 사용하여 프로그램의 정확성을 확인한다.

배열을 표시할 때는 16진수(Hexadecimal) 또는 10진수(Decimal) 표현 방식을 선택한다.

6. 프로시저를 두 번 호출하여 레지스터 보존 확인하기
테스트하려는 프로시저를 호출한 직후 같은 프로시저를 한 번 더 호출하여 레지스터가 보존되는지 확인한다.

asm
mov esi,OFFSET array
mov ecx,count
call CalcSum ; EAX에 합계 반환
call CalcSum ; 레지스터 보존 여부를 확인하기 위한 두 번째 호출
일반적으로 반환값은 EAX에 저장되므로 EAX는 원래 값으로 보존할 수 없다. 따라서 일반적으로 EAX를 입력 매개변수로 사용하지 않는 것이 좋다.

7. 배열 이름 대신 간접 주소 지정 사용하기
프로시저에 둘 이상의 배열을 전달할 계획이라면, 프로시저 내부에서 배열 이름을 직접 참조하지 않는다.

대신 프로시저를 호출하기 전에 ESI 또는 EDI에 배열의 오프셋을 저장한다. 그러면 프로시저 내부에서 [esi] 또는 [edi]와 같은 간접 주소 지정을 사용할 수 있다.

8. 프로시저 내부에서 사용하는 변수 선언 및 초기화하기
프로시저 내부에서만 사용할 변수가 필요하다면, .data 지시어로 변수를 선언하고 그 뒤에 .code 지시어를 사용한다.

asm
MyCoolProcedure PROC
.data
sum SDWORD ?
.code
mov sum,0
; 나머지 코드
이 변수는 C++이나 Java의 지역 변수와 달리 여전히 외부에서 접근할 수 있다. 하지만 프로시저 내부에 선언하면 해당 프로시저에서만 사용할 의도임을 명확하게 나타낼 수 있다.

또한 프로시저는 여러 번 호출될 수 있으므로, 내부에서 사용하는 변수는 실행 중 명령어를 통해 초기화해야 한다. 두 번째 호출에서 이전 호출의 값이 남아 사용되는 것을 방지하기 위해서다.

핵심 요약
디버거로 프로그램을 단계별 실행한다.

부호 있는 배열에는 음수를 포함한다.

입력 범위의 경계 전·경계·경계 후 값을 테스트한다.

길이가 다른 배열로 테스트한다.

Visual Studio의 Memory 창으로 배열을 확인한다.

프로시저를 두 번 호출하여 레지스터 보존을 확인한다.

배열의 오프셋을 레지스터로 전달하고 간접 주소 지정을 사용한다.

프로시저 내부 변수는 매번 적절하게 초기화한다.
